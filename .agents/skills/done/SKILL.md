# Finish Worktree Workflow

이 워크플로우는 워크트리에서 화면 개발 등의 작업이 끝난 후 코드를 정리, 커밋, 푸시하는 과정을 자동화합니다.

## Steps

1. **상태 확인 및 정리**:
   `git status` 및 `git diff`를 실행하여 변경된 내용을 확인합니다. 필요하다면 린트(lint)나 포맷팅(formatting)을 수행하여 코드를 정리합니다.
2. **코드 스테이징 및 커밋 (현재 브랜치)**:
   `git add .` 명령어를 통해 변경사항을 스테이징합니다. 변경사항을 분석하여 적절한 커밋 메시지를 생성하거나 사용자에게 커밋 메시지를 물어본 뒤, `git commit`을 진행합니다.
3. **현재 브랜치 푸시**:
   현재 브랜치 이름을 확인(`git branch --show-current`)하고, `git push origin <브랜치명> -u` 명령어로 GitHub에 변경사항을 푸시합니다.
4. **main 브랜치 병합 (Merge) 및 푸시**:
   원본 레포지토리 폴더(main 브랜치가 있는 부모 폴더)로 이동하여 `git status`를 확인합니다.
   - 만약 `main` 브랜치에 커밋되지 않은 변경사항이 있다면, 해당 변경사항을 함께 커밋할지 사용자에게 승인을 먼저 받습니다. (동의 시 커밋 진행)
   - 이상이 없다면 작업했던 워크트리의 브랜치를 `main` 브랜치로 병합(`git merge <작업브랜치명>`)합니다.
   - 병합된 `main` 브랜치를 `git push origin main` 명령어로 GitHub에 푸시합니다.
5. **결과 보고 및 워크트리 정리**:
   모든 푸시 및 병합이 성공적으로 완료되었음을 사용자에게 알립니다.
   작업이 모두 완료되었으므로, 해당 워크트리를 삭제할지(예: `git worktree remove <경로>`) 사용자에게 물어보고 원한다면 워크트리 삭제까지 진행합니다.
